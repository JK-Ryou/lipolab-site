2026-10-15 읽는 시간 약 10분 강의 내용으로 바로가기 강의정리노트 원본 열기
Q&A

강의 듣기 전, 이런 게 궁금하셨죠?

강의를 듣기 전에 흔히 하게 되는 질문 10개입니다. 답은 모두 이번 강의에서 다룬 내용입니다.

Q1. ChatGPT 같은 챗봇과 "Agent"는 뭐가 다른가요?

챗봇은 질문 하나에 답 하나를 주는 구조(single-turn)이고, 대화를 이어가려면 메모리가 따로 필요합니다. Agent는 한발 더 나가 도구를 직접 골라 쓰며 목표를 달성할 때까지 반복합니다. 그래서 일을 맡기는 관계가 됩니다. 사용자가 팀장이고 Agent가 팀원이며, 팀원이 한 일은 팀장이 검수합니다.

Q2. AI는 왜 가끔 틀린 말을 하나요? 믿어도 되나요?

생성형 AI는 학습한 내용을 바탕으로 확률에 따라 내용을 만들어내기 때문입니다. 그래서 근거 없이 그럴듯하게 말할 수 있습니다. 이를 보완하는 장치가 RAG(근거와 도메인 지식 제공)이고, Agent의 결과는 사람이 검수하는 loop를 둡니다.

Q3. 프롬프트만 잘 쓰면 AI를 잘 쓰는 건가요?

프롬프트는 재료 중 하나일 뿐입니다. AI에게 들어가는 컨텍스트는 5가지입니다. 프롬프트(명령), 시스템 프롬프트(역할), 도구 정보, RAG 문서(답안지), 장·단기 메모리. 강의의 출발점은 "팀장이 키워드를 알아야 팀원을 잘 시킨다"였고, 실습에서는 구체적으로, 역할을 주어 시키라고 했습니다.

Q4. 우리 회사 문서(약관, FAQ 등)를 AI가 알고 답하게 하려면?

RAG를 씁니다. 약관·FAQ 같은 문서를 저장소(VectorDB)에 두고, 질문이 들어오면 관련 내용을 찾아 근거를 남기며 답하게 합니다. AWS에서는 Bedrock의 Knowledge Bases가 이 역할입니다.

Q5. AI가 외부 시스템이나 도구와 연결되려면 어떻게 하나요?

연결 규격으로 MCP를 씁니다. Agent와 도구를 잇는 표준이라, 규격만 맞으면 도구를 바꿔 끼울 수 있습니다. AWS의 AgentCore gateway는 외부 MCP 등 도구를 쓸 때 사용하고, 서버를 직접 관리하지 않는 Lambda를 뒤에 붙일 수도 있습니다.

Q6. 만든 Agent는 어디에 올려서 운영하나요?

AWS의 AgentCore를 씁니다. runtime은 Agent를 서버로 배포하고, harness는 소스코드 없이 설정만으로 배포하며, policy & identity가 인증·권한을 맡습니다. EC2에도 올릴 수 있지만 그러면 세션 관리를 따로 개발해야 합니다.

Q7. 개발자가 아니어도 Claude Code로 뭔가 만들 수 있나요?

네. 오늘 실습이 그랬습니다. "S3 사용해서 정적 웹사이트 만들어줘." 한 줄로 시작해 테트리스를 만들어 배포하고, React + TypeScript + Vite + Cloudscape 포털까지 구축했습니다. 에러가 나면 그 내용을 Claude에게 그대로 전달하면 됩니다.

Q8. AI가 마음대로 일을 벌이면 위험하지 않나요?

안전장치가 있습니다. Plan mode는 작업 전에 계획부터 세워 빠진 부분을 바로잡게 하고, 권한 모드는 위험한 작업을 확인을 거쳐 진행합니다. 정보 수집·정리처럼 부담이 적은 일은 자동 수행이 편합니다. 작업 뒤에는 /review로 바꾼 곳만 점검할 수 있습니다.

Q9. 개인정보 삭제 같은 규칙을 매번 AI에게 말해줘야 하나요?

한 번 정해두면 됩니다. 반복되는 맥락과 규칙은 CLAUDE.md(지침), 반드시 지켜야 하는 것은 Hooks(강제), 반복되는 절차는 Skills(예: 웹서치 → 검증 → 초안)에 남깁니다. 무엇을 남길지는 실습 뒤 "남길 만한 규칙·절차를 제안만 해 달라"고 요청하면 Claude가 후보를 뽑아 줍니다.

Q10. 모델은 뭘 고르고, 비용은 어떻게 아끼나요?

/model로 Opus, Sonnet, Haiku 중에서 고르고, /effort로 추론 깊이를 정합니다. 강의에서는 Opus는 medium 정도로 쓰고, 가장 높은 단계는 오히려 자가당착에 빠지는 경우가 많다고 했습니다. Agent는 목표를 달성할 때까지 호출을 반복하니 토큰 과금이 늘어납니다. Sub-agent에 가벼운 모델을 따로 주면 비용을 줄이고 동시에 작업할 수 있고, 대화가 길어지면 /compact, 새로 시작하려면 /clear를 씁니다.

오늘 꼭 가져갈 3가지

  1. 키워드를 알면 잘 시킬 수 있다. Agent는 팀원이고 나는 팀장입니다. 결과 검수는 사람의 몫입니다.
  2. 지침은 CLAUDE.md, 강제는 Hooks, 절차는 Skills. 반복되는 것은 파일로 남깁니다.
  3. 구체적으로, 역할과 함께 시킨다. 에러가 나면 그대로 Claude에게 전달하면 됩니다.

원본 노트에서 공식 문서로 바로잡은 점 (자세한 근거는 워크북)

  • S3의 50TB는 "bucket 용량"이 아니라 객체 1개의 최대 크기이고, 저장 총량은 제한이 없습니다.
  • "세션끼리 대화가 공유되지 않는다"는 맞지만, CLAUDE.md와 자동 메모리는 세션을 넘어 이어집니다.
  • 노트의 "confection"은 compaction(대화 요약 압축)을 가리키는 것으로 보입니다.

PART 1

Agentic AI — Agent는 무엇으로 만들어지나

Agent = 모델 + 컨텍스트 + 도구 + 반복 루프, 그리고 사람의 검수

Agent가 일하는 방식

Context — 모델에게 주는 재료 5가지

  • 프롬프트: 모델에 내리는 명령
  • 시스템 프롬프트: 모델에 역할 부여
  • 도구 정보: 도구에 붙인 설명(schema, spec)
  • RAG 문서: 명령에 대한 "답안지"
  • 장·단기 메모리: 여러 턴을 이어가기 위한 기억

핵심 용어 한 줄씩

  • 생성형 AI: 확률 기반으로 다음 내용을 만들어냄
  • RAG: 근거와 도메인 지식을 찾아 붙임 (약관·FAQ → VectorDB)
  • Harness: 모델을 일하게 만드는 도구 + 컨텍스트 묶음
  • MCP: Agent가 외부 도구와 연결되는 표준 규격

PART 3

Claude Code 실습 — 만들고, 설정하고, 확장하기

처음엔 말로 시키고, 반복되는 규칙은 파일로 남긴다

실습한 것 4가지

  1. S3로 정적 웹사이트 — "S3 사용해서 정적 웹사이트 만들어줘." 정적 사이트는 호출할 때마다 같은 내용을 보여줍니다.
  2. 테트리스 — S3에 저장하고 CloudFront를 앞에 두는 방식으로 배포했습니다.
  3. 포털 구축 — React + TypeScript + Vite + Cloudscape 프로젝트를 만들고 개발 서버를 실행했습니다.
  4. 마무리 프롬프트 — 실습 뒤 바꾼 파일과 이유를 정리하고, 남길 규칙을 제안받았습니다.
