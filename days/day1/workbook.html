PART 1

1. Agentic AI — "팀장이 똑똑해야 팀원을 잘 시킨다"

Agent = 모델(두뇌) + 컨텍스트(재료) + 도구(손발) + 반복 루프(일하는 방식), 그리고 사람의 검수

1-1. 모델에서 Agent까지

단계하는 일IT에 빗대면
ML / DL학습한 내용을 바탕으로 예측까지분류기, 추천 모델
생성형 AI학습한 내용으로 생성까지. 확률을 기반으로 함자동완성의 확장판
Agent도구를 골라 쓰며 목표 달성까지 반복오케스트레이터가 붙은 워크플로 엔진

학습에는 한계가 있어서, 인간의 인지·학습 과정이 결국 필요해진다는 맥락에서 "learning"을 짚었습니다. Agent가 한 일은 검토·검수하는 loop가 필요하고, 이것이 Human Role입니다.

Claude Code 용어집은 이 검수를 Verification loop로 부릅니다. 테스트나 빌드처럼 Claude가 직접 돌릴 수 있는 확인 수단을 주고, 통과할 때까지 반복하게 하는 방식입니다. 이 확인 수단이 없으면 "끝났다"를 판단하는 것은 Agent 자신뿐입니다.

용어집의 Agentic loop 정의는 "맥락 수집 → 행동 → 결과 검증을 끝날 때까지 반복"이며, 노트의 루프 설명과 같은 구조입니다.

1-2. 내가 남긴 질문: "앞의 내용이 정해지지 않으면 뒤의 데이터가 확정되지 않는가?"

생성형 AI는 '확률'을 기반으로 한다는 설명 뒤에 남기신 질문입니다.

답: 맞습니다. 그리고 "확정"이 두 겹으로 나뉩니다.

  1. 분포는 앞이 정해지면 정해집니다. 모델은 지금까지의 토큰을 조건으로, 다음에 올 수 있는 모든 토큰에 점수(확률)를 매깁니다. 예를 들어 "하늘은 ___" 뒤에 "파랗다 62%, 맑다 21%…" 같은 목록이 나옵니다.
  2. 그 목록에서 실제로 하나를 뽑는 단계(샘플링)가 확률적입니다. 확률이 낮은 토큰도 뽑힐 수 있고, 한 번 다른 토큰이 뽑히면 이후 문장이 갈라질 수 있습니다.
  3. temperature는 이 목록의 모양을 바꾸는 손잡이입니다. 0에 가까우면 상위 토큰이 지배해 결과가 거의 같아지고, 높이면 낮은 확률의 토큰이 더 자주 뽑혀 다양해집니다.

실무 의미 temperature를 낮추면 재현성은 좋아지지만 정확성이 보장되지는 않습니다. 모델의 1순위 답이 틀렸다면 낮은 temperature는 같은 오답을 매번 내놓습니다. 그래서 RAG로 근거를 붙이고, 평가셋과 검증 loop로 확인해야 합니다.

IT 비유: 해시 함수처럼 "같은 입력은 항상 같은 출력"이 아니라, 가중치가 걸린 주사위를 매 글자마다 굴리는 구조에 가깝습니다. 주사위의 눈 확률은 앞 글자가 정하고, 실제 눈은 굴려야 나옵니다.

근거의 한계

위 설명은 교육용 해설 문서(KodeKloud) 한 곳에서 확인했습니다. Anthropic 플랫폼 용어집 접근은 승인되지 않아 읽지 못했고, Claude 최신 모델의 temperature 파라미터 동작과 기본값은 확인하지 못했습니다.

1-3. Context와 Harness

구성요소노트 정리보강
프롬프트모델에 내리는 명령
시스템 프롬프트모델에 역할을 부여Claude Code는 시작 시 핵심 지침을 가장 먼저 로드합니다.
도구 정보도구에 설명(schema, spec)을 붙이고, 쓸지 말지는 모델이 결정MCP 도구는 이름만 먼저 올리고 전체 schema는 필요할 때 불러옵니다(MCP Tool Search). 도구가 많아도 컨텍스트가 덜 차도록 한 장치입니다.
RAG 문서명령에 대한 "답안지"
단기 메모리세션 대화 = context window컨텍스트가 한계에 가까워지면 오래된 도구 출력부터 지우고, 그다음 대화를 요약합니다(compaction). 노트의 "confection"은 이 compaction으로 보입니다.
장기 메모리세션을 넘어 기억하는 것Claude Code는 CLAUDE.md(내가 쓰는 지침)와 auto memory(Claude가 스스로 적는 메모, 시작 시 앞 200줄 또는 25KB 로드)로 세션 사이를 잇습니다.

용어 정리: "harness"는 두 가지 뜻으로 쓰였습니다

  • 일반 개념 모델을 유능한 Agent로 만드는 도구, 컨텍스트 관리, 실행 환경의 묶음. 용어집은 "Claude Code가 harness, Claude는 그 안의 모델"이라고 설명합니다.
  • AgentCore의 Harness 기능 모델, 시스템 프롬프트, 도구를 지정해 API 한 번으로 Agent를 정의·호출하는 관리형 Agent 루프. 세션마다 격리된 microVM에서 실행됩니다.

IT 비유: 앞의 것은 "프레임워크"라는 개념이고, 뒤의 것은 그 프레임워크를 관리형으로 제공하는 "PaaS 상품"입니다. 노트의 두 설명은 서로 모순되지 않습니다.

1-4. RAG

RAG는 근거와 domain knowledge를 보완합니다. 약관·FAQ 같은 문서는 VectorDB에 저장해 두고, 질문이 들어오면 관련 내용을 찾아 근거를 남기며 답합니다.

IT 비유: 시험을 "오픈북"으로 치르는 것과 같습니다. 모델이 외운 것 대신, 찾아본 근거로 답하게 합니다.

1-5. MCP

MCP는 Agent의 통합 규격(표준)입니다.

  • Claude Code 용어집: AI 도구를 외부 데이터 소스·서비스와 연결하는 개방형 표준. MCP 서버는 /mcp, claude mcp add, .mcp.json, 플러그인으로 연결합니다.
  • Anthropic이 2024-11-25에 공개했고, 2025-12에 Linux Foundation 산하 Agentic AI Foundation(AAIF)으로 기부되었다고 합니다(위키백과 요약).
  • 같은 문서에 따르면 최신 spec 개정이 2026-07-28에 확정되었고, 프로토콜 수준의 세션 추적을 없애 stateless로 바뀌었으며 sampling과 roots는 deprecated입니다. 공식 spec 원문으로는 확인하지 못했으니 도입 전에 확인이 필요합니다.
  • IT 비유: USB-C 포트. 어떤 Agent든, 어떤 도구든 같은 규격으로 꽂으면 동작합니다.

2-3. S3와 CloudFront — 노트의 수치 확인

노트의 표현확인 결과
"bucket 1개 50TB (무제한)"정정 AWS FAQ: 객체 1개의 크기는 0바이트에서 최대 50TB이고, 저장할 수 있는 총 용량과 객체 수는 제한이 없습니다. 단일 PUT은 최대 5GB이며 100MB 넘는 객체는 multipart 업로드를 권장합니다. 즉 50TB는 bucket이 아니라 객체 기준입니다.
"CF 데이터센터 전세계 800여개"대체로 일치 CloudFront 소개 페이지: 750+ POP(100+ 도시, 50+ 국가), 리전 엣지 캐시 15개, 별도로 embedded POP 1,140+개. 페이지에 기준일은 없습니다.
"국내 10여개"확인하지 못함 공식 페이지는 서울을 POP 도시로 올려놨지만 한국의 개수는 밝히지 않았습니다.
"CF = CDN = 캐시 서버"맞음 사용자와 가까운 거점에 복사본을 두는 방식입니다.

정적 웹사이트 실습 시 알아둘 점

  • CloudFront와 S3 웹사이트 엔드포인트 사이의 연결은 HTTP만 가능합니다(AWS re:Post). 사용자에게 HTTPS를 주려면 CloudFront의 Viewer Protocol Policy를 "Redirect HTTP to HTTPS" 또는 "HTTPS only"로 설정합니다.
  • 커스텀 도메인을 쓸 때 ACM 인증서는 us-east-1 리전의 것이어야 합니다.

3. Claude Code — 설정하고 확장하기

사용 환경은 CLI가 기능이 조금 더 많다고 했습니다. 용어집에서는 CLI, VS Code, JetBrains, Desktop, claude.ai를 모두 "surface"라 부르며 같은 엔진을 공유한다고 설명합니다. 다만 기능 지원 범위는 surface마다 다를 수 있어, 이번 조사에서 항목별 차이를 비교하지는 못했습니다.

3-1. 기본 설정 명령

명령공식 문서 설명
/model모델 선택. 별칭 opus, sonnet, haiku, fable, 그리고 opusplan(계획 단계는 opus, 실행은 sonnet). 별칭이 가리키는 버전은 제공 업체(provider)마다 다릅니다.
/effort적응형 추론의 깊이. 수준은 low, medium, high, xhigh, max. "표에 없는 모델은 effort를 지원하지 않음"
/compact지금까지의 대화를 요약해 컨텍스트를 확보합니다. 노트의 이 항목은 비어 있었습니다.
/clear빈 컨텍스트로 새 대화를 시작합니다(별칭 /reset, /new). 이전 대화는 /resume으로 불러올 수 있습니다.
/init, /memory/init은 CLAUDE.md 초안을 만들고, /memory는 CLAUDE.md 편집과 auto memory 관리를 합니다.
/code-review현재 diff를 점검해 정확성 버그를 찾습니다. /review는 이것의 별칭입니다. 노트의 "바꾼 곳만 점검(as-is, to-be 비교)"과 맞습니다.

effort — 노트의 두 주장 확인

  • "보통 새로 나온 모델들만 적용" → 맞음 목록에 있는 모델만 지원합니다.
  • "opus medium" → 맞음 Opus 5.5, Sonnet 5.5, Haiku 5.5의 기본값이 medium이고, 문서는 Opus 5.5의 medium이 Opus 5의 high와 코딩·지식업무 평가에서 같거나 낫다고 밝힙니다.
  • "ex-high는 자가당착에 빠지는 경우가 많다" → 부분 일치 문서가 "overthinking" 경향을 경고하는 것은 max입니다("점진적 이득이 줄고 과하게 생각하기 쉬우니 넓게 쓰기 전에 테스트"). xhigh는 "더 깊은 추론, 더 큰 토큰 비용"으로만 설명됩니다.

권한 모드

"최근의 default = auto mode(명령 자동 수행). 위험한 작업은 권한 모드로 진행하는 것이 안전."

모드묻지 않고 실행하는 것적합한 상황
default (CLI에서는 Manual)읽기만모든 동작을 직접 검토, 민감한 작업
acceptEdits읽기, 파일 편집, 일반 파일시스템 명령검토하며 코드를 다듬을 때
plan조사·제안만. 소스 편집 없이 계획 승인 후 진행작업 전 계획 점검
auto별도 분류 모델이 대신 검토하고 대부분 실행자동 수행이 편한 작업
dontAsk / bypassPermissions(각각 거부 / 모두 허용)샌드박스나 컨테이너 등 격리 환경
  • Shift+Tab으로 모드를 순환합니다. 이때 auto에서 한 번 누르면 default로, 이후 default → acceptEdits → plan 순입니다. Plan은 /plan으로도 진입합니다.
  • 노트와 일치 v2.1.283 이상에서 auto가 대화형 터미널·VS Code 세션의 시작 모드입니다(이전 버전은 Pro·Max·Team 요금제에 한함). 주의: 설정값 이름 default는 시작 모드가 아니라 Manual을 뜻합니다. 또한 조직 정책으로 auto가 꺼질 수 있습니다.

CLAUDE.md

  • 강의: 위치에 따라 적용 범위가 달라진다.
  • 범위는 세 층입니다. 관리 정책(조직 전체, 예: Linux는 /etc/claude-code/CLAUDE.md), 사용자(~/.claude/CLAUDE.md), 프로젝트(./CLAUDE.md 또는 ./.claude/CLAUDE.md). 발견된 파일은 덮어쓰지 않고 이어 붙여서 컨텍스트에 들어갑니다(넓은 범위에서 좁은 범위 순). 하위 폴더의 파일은 필요할 때 로드됩니다.
  • 파일당 200줄 이하 권장. 길수록 컨텍스트를 더 쓰고 준수율이 떨어집니다. 서로 모순되는 지침이 있으면 Claude가 임의로 하나를 고를 수 있습니다.
  • 프로젝트 루트의 CLAUDE.md는 compaction 뒤에도 디스크에서 다시 읽혀 살아남습니다. 대화 속에서만 준 지시는 사라질 수 있습니다.
  • "md 파일은 Claude로 만들어낼 수 있다" → /init이 코드베이스를 분석해 초안을 만들어 줍니다.

3-3. Hooks 자세히

Hook은 강제, JSON으로 작성. 예시 해석: "도구를 사용한 후에(PostToolUse), 파일을 쓰고 고치는 도구를 불러서(matcher), 개인정보를 수정".

구조는 이벤트 → matcher → handler 3단계입니다. 아래는 공식 문서의 PostToolUse 예시이며, Write 또는 Edit 호출 뒤에 점검 스크립트를 실행합니다. 노트의 해석과 같은 구조입니다.

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/lint-check.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}

handler 종류

command(쉘), http, mcp_tool, prompt(LLM), agent(서브에이전트). 입력은 stdin으로 JSON이 들어옵니다(tool_name, tool_input 등).

종료 코드

exit 2만 차단합니다(PreToolUse는 도구 호출을 막음). exit 1은 차단하지 않습니다. 정책을 강제하려면 반드시 exit 2를 쓰세요.

설계 시 주의: "개인정보 수정"을 PostToolUse에 걸면 무엇이 되나

PostToolUse에서 exit 2는 "도구가 이미 실행된 뒤라서" 오류 메시지를 Claude에게 보여 줄 뿐입니다. 따라서 개인정보가 파일에 쓰이는 것 자체를 막으려면 PreToolUse, 쓴 뒤 정정·정리를 시키려면 PostToolUse가 맞습니다. 금융 환경이라면 어느 쪽 요구인지 먼저 정하세요.

이벤트 종류 (노트에서는 이미지로만 제시)

문서에는 30개 이상의 이벤트가 있습니다. 자주 쓰는 것만 묶었습니다.

구분이벤트
세션SessionStart, SessionEnd, Stop(응답 완료), StopFailure
입력UserPromptSubmit(프롬프트 제출 직후 처리 전), UserPromptExpansion
도구PreToolUse, PostToolUse, PostToolUseFailure, PostToolBatch, PermissionRequest, PermissionDenied
위임·작업SubagentStart, SubagentStop, TaskCreated, TaskCompleted
컨텍스트·설정PreCompact, PostCompact, InstructionsLoaded, ConfigChange, FileChanged

3-4. Skills와 Sub-agents

Skills

도구 절차를 규칙으로 만든 것. /이름 호출과 description 기반 자동 호출 두 가지. frontmatter의 name이 호출명, description이 "언제 쓰는지".

위 내용은 공식 문서에서도 확인됩니다. 추가로 알아둘 점:

  • 위치: 개인 ~/.claude/skills/<이름>/SKILL.md, 프로젝트 .claude/skills/<이름>/SKILL.md, 플러그인 안(/플러그인:스킬로 호출). 이름이 겹치면 enterprise > personal > project 순입니다.
  • description은 항상 컨텍스트에 올라 있고, 본문은 호출될 때만 로드됩니다. 그래서 description이 자동 호출의 품질을 좌우합니다.
  • disable-model-invocation: true이면 사람만 호출할 수 있고, user-invocable: false이면 Claude만 호출합니다. SKILL.md는 500줄 이하 권장.
  • "표준이라 Codex에도 바로 쓴다" → Skills는 여러 AI 도구에서 쓰이는 개방형 Agent Skills 표준을 따릅니다. 다만 Claude Code 전용 필드를 쓰면 claude.ai 업로드·패키징에서 거부될 수 있습니다. Codex에서의 호환 여부는 공식 확인을 못 했습니다.
---
name: fix-issue
description: Fix a GitHub issue by number. Use when the user asks to resolve an issue.
disable-model-invocation: true
---

Fix GitHub issue $ARGUMENTS following our coding standards.

1. Read the issue description
2. Implement the fix and write tests
3. Create a commit

위는 공식 문서의 예시를 줄여 옮긴 것입니다.

Sub-agents

강의: 메인과 모델 설정을 다르게, 역할을 따로 설정. 토큰 비용 효율화와 동시 작업이 장점.

  • 서브에이전트는 자체 컨텍스트 창, 별도 시스템 프롬프트, 도구 접근, 독립된 권한을 가지고 결과만 돌려줍니다. 그래서 긴 검색 결과나 로그가 메인 대화를 채우지 않습니다.
  • 필수 필드는 name과 description. 선택으로 tools, model(sonnet, opus, haiku, fable, 전체 ID, inherit), permissionMode, effort 등. 위치는 프로젝트 .claude/agents/, 사용자 ~/.claude/agents/.
  • 쓰기 좋은 때: 큰 부수 작업, 도구 제한이 필요할 때, Haiku 같은 저렴한 모델로 돌리고 싶을 때. 반대로 잦은 왕복이 필요하거나 빠른 수정에는 메인 대화가 낫습니다. 기본 제공: Explore, Plan, general-purpose.
  • "요즘은 Agent 자체를 Multi-Agent(A2A)로" → 용어집에 Claude Code의 실험 기능 agent teams(독립 세션 여러 개가 공유 작업 목록으로 협업, 기본 비활성)가 있습니다. "A2A"라는 이름의 프로토콜이 노트의 맥락과 같은지는 확인하지 못했습니다.
---
name: code-reviewer
description: Reviews code for quality and best practices. Use after code changes.
tools: Read, Glob, Grep
model: sonnet
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.

3-5. Plugin과 세션

누군가 만든 스킬 등이 포함된 뭉텅이를 설치해 사용.

  • 플러그인은 skills, agents, hooks, MCP servers 등을 한 단위로 설치하는 폴더입니다. 터미널에서 /plugin으로 Discover 탭에서 설치하고, 설치 범위는 user, project, local 중에서 고릅니다.
  • 주의: 플러그인은 사용자 권한으로 코드를 실행할 수 있습니다. 설치 전에 검토가 필요하고, 활성화된 플러그인의 skill·agent 이름과 설명은 매 턴 컨텍스트를 차지합니다(공식 마켓플레이스 플러그인은 Context cost 추정치가 표시됩니다).

세션 간 대화는 공유되지 않는다 — 단, 예외가 있습니다

  • 세션을 여러 개 열면 서로 대화 데이터가 공유되지 않으니, A/B 기능을 각각 해볼 때는 세션을 따로 열거나 /clear를 쓰세요.
  • 맞습니다. 세션마다 독립된 컨텍스트 창을 가지고, /clear는 새 세션을 시작합니다(이전 세션은 보관되어 /resume으로 복귀).
  • 예외: CLAUDE.md와 auto memory는 디스크에 있어서 새 세션에도 로드됩니다. 즉 "대화"는 공유되지 않지만 "지침과 학습 메모"는 이어집니다. 실습 A와 B의 결과가 서로 오염되지 않게 하려면 이 파일들의 내용도 점검하세요.

REVIEW

7. 복습 문제

동료와 함께 풀어 보세요. 질문을 누르면 답이 열립니다.

Q1. Agent를 구성하는 요소를 한 문장으로 말해 보세요.

모델 + 컨텍스트 + 도구 + 반복 루프, 그리고 결과를 확인하는 사람의 검수가 필요합니다. 도구와 컨텍스트를 묶어 harness라고도 부릅니다.

Q2. 같은 질문에 모델의 답이 매번 조금씩 다른 이유는?

다음 토큰의 확률 목록에서 하나를 뽑는 샘플링 단계가 확률적이기 때문입니다. temperature를 낮추면 재현성은 좋아지지만 정확성이 보장되지는 않습니다.

Q3. 컨텍스트가 가득 차면 어떤 일이 일어나고, 무엇이 살아남나요?

오래된 도구 출력부터 지우고 대화를 요약합니다(compaction). 프로젝트 루트의 CLAUDE.md와 auto memory는 디스크에서 다시 읽혀 살아남지만, 대화에서만 준 지시는 사라질 수 있습니다.

Q4. "민감한 파일은 절대 수정하지 마"라는 규칙을 반드시 지키게 하려면 CLAUDE.md와 Hooks 중 무엇을 쓰나요? 어떤 이벤트와 종료 코드가 필요한가요?

Hooks입니다. CLAUDE.md는 컨텍스트일 뿐 강제가 아닙니다. 도구 실행 전에 막으려면 PreToolUse 이벤트에서 exit 2로 종료합니다. exit 1은 차단하지 않습니다.

Q5. S3의 50TB와 "무제한"을 정확하게 설명해 보세요.

객체 하나의 최대 크기가 50TB이고, bucket에 저장하는 총 용량과 객체 수에는 제한이 없습니다. 단일 PUT은 5GB까지이고 100MB를 넘으면 multipart 업로드를 권장합니다.

Q6. 서브에이전트를 쓰면 좋은 경우와 메인 대화가 나은 경우를 하나씩 말해 보세요.

좋은 경우: 긴 검색 결과가 메인 대화를 채우는 부수 작업이거나, 저렴한 모델로 돌리고 싶을 때. 메인이 나은 경우: 잦은 왕복과 수정이 필요한 작업이나 빠른 소규모 수정.

Q7. 세션 A에서 한 대화를 세션 B에서 볼 수 있나요? 공유되는 것은 무엇인가요?

대화는 볼 수 없습니다. 다만 CLAUDE.md와 auto memory는 디스크에 있어서 새 세션에도 로드됩니다.

Q8. 정적 웹사이트에 HTTPS를 적용하려면 S3만으로 되나요?

S3 웹사이트 엔드포인트는 HTTP만 제공하므로, CloudFront를 앞에 두고 Viewer Protocol Policy를 HTTPS로 설정합니다. 커스텀 도메인의 ACM 인증서는 us-east-1에서 발급해야 합니다.

Q9. 실습이 끝나고 어떤 프롬프트를 던지나요? 왜 "만들지는 마세요"를 붙이나요?

만들고 바꾼 파일과 이유를 정리시키고, CLAUDE.md와 Skill로 남길 후보를 제안받는 프롬프트입니다. 무엇을 영구 규칙으로 남길지는 사람이 결정하도록, 제안 단계에서 멈추게 합니다.
