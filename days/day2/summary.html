Q&A

강의 듣기 전, 이런 게 궁금하셨죠?

강의를 듣기 전에 흔히 하게 되는 질문 10개입니다. 답은 모두 이번 강의에서 다룬 내용입니다.

Q1. MCP가 뭔가요? API나 SDK랑 어떻게 다른가요?

MCP는 Agent가 외부 도구·서비스와 연결되는 표준 규격(프로토콜)입니다. API가 "창구 하나"라면, MCP는 "어떤 창구든 같은 방식으로 끼울 수 있는 규격"입니다. USB-C 포트에 비유할 수 있습니다. SDK는 특정 언어에서 API를 쉽게 쓰게 해주는 라이브러리이고, MCP는 AI Agent와 도구가 대화하는 프로토콜 수준의 표준입니다.

Q2. 로컬 MCP와 원격 MCP는 언제 각각 쓰나요?

내 데이터를 활용하거나 혼자 쓴다면 로컬(stdio)이 적합합니다. 개인 PC 자원을 쓰기 때문에 많이 돌리면 느려질 수 있고, 도구가 50개를 넘으면 MCP 서버를 정리하는 것이 좋습니다. 팀과 함께 쓰거나 서비스로 제공하려면 원격(streamable HTTP)을 씁니다. AWS AgentCore Gateway가 원격 MCP 서버를 관리형으로 제공합니다.

Q3. RDB, Graph DB, Vector DB 중 우리 업무엔 뭘 써야 하나요?

일반적인 업무 데이터(고객, 상품, 거래 등)는 RDB를 씁니다. 개념들 사이의 관계망을 다루는 온톨로지 구축에는 Graph DB, FAQ나 문서를 유사도로 검색해야 하는 RAG에는 Vector DB가 필요합니다. 오늘 실습의 고객·상품 데이터는 RDB(Aurora MySQL)였습니다.

Q4. 스키마를 처음부터 잘 설계해야 한다는 게 왜 중요한가요?

스키마를 나중에 추가하면 이전 데이터에 null이 생깁니다. 데이터 일관성이 깨지고 이후 조회·분석이 복잡해집니다. PK(Primary Key)처럼 식별자 역할을 하는 필드를 바꾸는 것은 더 어렵습니다. 처음 설계를 신중하게 해야 하는 이유입니다.

Q5. SQL CRUD와 HTTP CRUD는 같은 건가요?

개념은 같고 표현이 다릅니다. 만들고(Create), 읽고(Read), 고치고(Update), 지운다(Delete)는 의미는 동일합니다. SQL은 INSERT / SELECT / UPDATE / DELETE로, HTTP는 POST / GET / PUT / DELETE로 표현합니다. API가 DB 위에서 SQL을 래핑해 제공하는 구조라서 두 레이어가 나란히 존재합니다.

Q6. "자연어로 DB를 조회한다"는 게 실제로 어떻게 동작하나요?

① 사용자가 자연어로 질문합니다. ② Agent(모델)가 사용할 도구(API)를 고릅니다. ③ 도구가 HTTPS 요청을 만들어 서버에 보냅니다. ④ 서버가 SQL을 실행합니다. ⑤ 결과가 도구 → Agent → 사용자 순으로 전달됩니다. 오늘 실습에서 이 전 과정을 한 번에 확인했습니다.

Q7. "5명만 찾아줘"라고 했는데 왜 SQL에 LIMIT이 없었나요?

강의 중 실제로 나온 질문입니다. 모델이 "5명만"이라는 조건을 SQL의 LIMIT이 아니라 응답 출력 단에서 처리했을 가능성이 있습니다. Agent 응용에서 자연어 조건이 어느 레이어에서 적용되는지 확인하는 것이 중요합니다. 조건을 SQL 레이어에 반영하려면 프롬프트를 더 구체적으로 주거나, MCP 도구 명세에 명시하는 방법이 있습니다.

Q8. GET과 POST는 뭐가 다른가요?

GET은 데이터 조회에, POST는 데이터 생성 또는 복잡한 요청에 씁니다. GET은 URL에 파라미터가 드러나고, POST는 요청 본문(body)에 데이터를 담습니다. 오늘 실습에서 MCP 연결에 POST를 쓴 이유는 MCP 프로토콜이 도구 이름과 입력값을 JSON 본문에 담아 전달하는 방식으로 설계되어 있기 때문입니다.

Q9. AI가 잘못 답하는 경우(할루시네이션)를 어떻게 줄이나요?

세 가지 접근이 있습니다. ① 데이터의 질 관리: AI는 근거 데이터가 부정확하면 잘못 답합니다. 최신성·정확성과 분포 변화를 지속적으로 모니터링해야 합니다. ② 프롬프트: "모르면 모른다고 해"처럼 명확한 가이드를 줍니다. ③ 결과 검증: GenAI는 확률 기반이므로 항상 검증합니다. 특히 데이터 정책이 바뀌면 결과가 크게 달라질 수 있습니다.

Q10. MCP 서버를 직접 만들어 Claude Code에 연결하면 무엇을 할 수 있나요?

내 업무 데이터나 사내 시스템을 Claude Code에서 자연어로 다룰 수 있게 됩니다. "FastMCP 써서 엑셀 파일을 MCP 서버로 만들어줘"처럼 요청하면, 엑셀 데이터를 Claude Code에서 직접 질의할 수 있습니다. 혼자 쓴다면 stdio(로컬), 팀에 배포하려면 streamable HTTP(원격) 방식으로 구성합니다.

오늘 꼭 가져갈 3가지

  1. MCP = 도구를 연결하는 규격. 직접 만들거나 기존 것을 가져다 씁니다. 혼자 쓰면 로컬, 팀과 함께라면 원격입니다.
  2. 자연어 조회는 레이어가 여럿. 자연어 → Agent → API → SQL 순서로 처리되며, 조건이 어느 레이어에 적용되는지 확인해야 합니다.
  3. 결과는 항상 검증. 데이터의 질과 최신성을 관리하고, 프롬프트에 "모르면 모른다고 해"를 명시합니다.

강의 중 확인된 검증 포인트 (자세한 근거는 워크북)

  • "5명만 찾아줘" 질문에서 SQL에 LIMIT이 없었습니다. Agent가 조건을 어느 레이어에서 처리하는지 확인이 필요합니다.
  • MCP 연결에 POST를 쓴 이유는 HTTP 메서드의 일반 규칙이 아니라 MCP 프로토콜 설계 때문입니다.

PART 1

MCP — Agent가 외부 도구를 쓰는 방법

MCP = 도구 명세 + 실행 코드 + 인증 정보 + 전송 방식. 직접 만들거나, 기존 것을 가져다 쓰거나.

일반 앱과 Agent 앱의 차이

일반 Application

모델을 사용하지 않습니다. 개발자가 정해 놓은 로직대로만 동작합니다.

Agent Application

모델이 판단하고 도구를 고릅니다. 도구는 직접 만들거나, MCP로 외부 도구를 연결합니다.

MCP 구성요소 4가지

요소역할
도구 명세MCP가 어떤 일을 하는지 설명 — 모델이 읽는 "사용 설명서"
실행 코드MCP 서버 그 자체. 실제로 일하는 부분
인증 정보DB·API 등 인가된 사용자만 접근 가능하게 (내부용이라면 필수)
전송 방식로컬(stdio) 또는 원격(streamable HTTP) 중 선택

로컬 vs 원격 — 전송 방식 선택

로컬 (stdio)

  • 개인 PC 자원을 사용
  • 많이 돌리면 PC가 느려질 수 있음
  • 나만 쓸 때, 내 데이터를 활용할 때 적합
  • ex. Kiro — 도구 50개 초과 시 "MCP 서버 off" 권장

원격 (streamable HTTP)

  • 서버에서 실행, 팀과 함께 쓸 때 적합
  • ex. AgentCore Gateway — 원격 MCP 서버를 관리형으로 제공

MCP 서버 만들기 2단계

  1. 서버 파일 만들기 — "FastMCP 써서 엑셀 파일을 MCP 서버로 만들어줘." Claude Code에 요청하면 됩니다.
  2. Claude Code에 등록 — "내가 만든 MCP 서버를 연결해줘." 등록 후 한 번 껐다 켜야 반영됩니다.

DB & SQL — 데이터를 담고 꺼내는 구조

RDB는 일반 업무용, Graph DB는 관계망, Vector DB는 RAG — 목적에 맞게 고릅니다

DB의 종류

종류특징언제 쓰나

RDB 핵심 개념

스키마(Schema)

데이터의 구조와 규칙을 정의한 메타데이터. PK(Primary Key)로 각 행을 식별합니다. 중간에 추가하면 이전 데이터에 null이 생기므로 처음 설계가 중요합니다.

DB 연결 정보 4가지

  • 엔드포인트: 어떤 DB에 접속할지 (서버 주소)
  • 포트: 접속 통로 번호
  • 사용자 정보: 인가된 사용자 확인
  • DB/table 이름: 필요한 데이터 위치

PART 3

API — 시스템끼리 대화하는 창구

API = 정해진 방식으로만 요청하고 결과를 받는 창구. 내부 동작 방식을 몰라도 됩니다.

API가 필요한 이유

추상화

내부 동작 방식 없이 API 호출 방법만 알면 원하는 데이터를 검색·조회할 수 있습니다.

보안과 통제

정해진 방식으로만 요청과 결과를 주고받아, 데이터 접근 방식을 통제합니다.

데이터 조회 흐름의 변화

오늘 실습 구성

Aurora MySQL + API Gateway + AgentCore Gateway

자연어 질문 → Agent가 MCP를 통해 API 호출 결정 → API가 SQL 실행 → 결과 반환 → 모델이 자연어로 답

검증과 안정성 평가

할루시네이션 대응

  • 근거 데이터가 없으면 만들어낼 수 있음
  • 프롬프트에 "모르면 모른다고 해" 명시
  • 산출물이 제대로 나왔는지 항상 확인

데이터 질 관리

  • 최신성·정확성 지속 모니터링
  • 데이터 분포·정책 변화 시 결과가 크게 바뀔 수 있음
  • GenAI는 확률 기반이므로 결과를 항상 검증
